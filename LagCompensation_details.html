Lag Compensation

Unreal Engine 5 기반 Server-Side Rewind / SubTick 유사 지연 보상 시스템

C++ Unreal Engine 5 Multiplayer Network Programming Server-Side Rewind SubTick
// 01 — OVERVIEW

Server-Side Rewind

Lag Compensation은 멀티플레이 FPS에서 네트워크 지연으로 인해 발생하는 사격 판정 문제를 해결하기 위해 제작한 Server-Side Rewind 기반 지연 보상 시스템입니다.

클라이언트가 사격한 시점의 서버 시간을 함께 전송하고, 서버는 해당 시간의 과거 액터 위치를 복원한 뒤 충돌 판정을 수행하고 다시 현재 위치로 복구합니다.

특히 Unreal Engine의 서버-클라이언트 구조를 기반으로 프레임별 Transform 데이터를 기록하고, 사격 시점의 앞뒤 프레임을 보간하여 원하는 시점의 위치와 회전값을 계산하도록 구현했습니다.

이 방식은 Counter-Strike의 SubTick과 유사하게 서버의 특정 프레임에 양자화된 위치만 사용하는 것이 아니라 두 프레임 사이의 값을 보간하여 보다 정확한 사격 시점을 계산하는 것을 목표로 합니다.

// 02 — IMPLEMENTATION

What I Worked On

01

Frame Snapshot

액터의 위치, 회전 및 타임스탬프를 프레임 단위로 저장하는 Snapshot 구조 구현

02

Frame History

서버에서 움직이는 액터의 과거 Transform을 일정 시간 동안 기록하고 오래된 데이터를 자동으로 제거

03

SubTick Interpolation

사격 시점의 앞뒤 프레임을 검색하고 두 Transform 사이를 보간하여 정확한 Target Time의 위치를 계산

04

Server-Side Rewind

서버에서 모든 등록된 움직이는 액터를 과거 사격 시점으로 되돌린 후 충돌 판정을 수행

05

Actor Restore

충돌 판정이 끝난 후 액터들의 위치와 회전을 현재 시점으로 복구

06

Server RPC

클라이언트의 사격 정보를 Server Reliable RPC를 통해 서버로 전달하고 서버에서 실제 판정을 수행

07

Network Authority

과거 위치 기록과 되감기 판정을 서버에서만 수행하도록 Authority를 기준으로 로직을 분리

08

Debug Visualization

과거 위치와 현재 위치를 디버그 캡슐 및 구로 표시하여 네트워크 지연과 Rewind 결과를 시각적으로 확인

// 03 — TECHNICAL DETAILS

How It Works

서버에서는 Lag Compensation Component가 매 Tick마다 액터의 현재 위치와 회전을 FFrameSnapshot으로 저장합니다. 테스트 프로젝트에서는 최대 1초의 기록을 유지하도록 구성했습니다.

클라이언트가 사격하면 현재 서버 시간을 FireTime으로 함께 전송합니다. 서버는 이 시간을 기준으로 History에서 FireTime보다 이전과 이후에 존재하는 두 프레임을 검색합니다.

이후 두 프레임의 Transform을 Linear Interpolation하여 실제 사격 시점의 위치와 회전을 계산합니다. 이를 통해 서버 Tick 사이에서 발생한 사격도 보다 정확하게 판정할 수 있도록 구현했습니다.

계산된 과거 Transform을 이용해 서버의 액터들을 과거 상태로 되돌린 다음 Line Trace를 수행하고, 판정이 끝나면 다시 현재 Transform으로 복구합니다.

// 04 — DESIGN

Network Design

되감기 기능을 담당하는 GameMode와 개별 액터의 과거 데이터를 관리하는 Lag Compensation Component를 분리했습니다.

또한 Interface를 사용하여 GameMode가 특정 Character 구현에 직접 의존하지 않도록 구성했습니다. 이를 통해 캐릭터뿐만 아니라 추후 다른 움직이는 액터에도 동일한 Lag Compensation 시스템을 적용할 수 있습니다.

테스트 편의를 위해 캐릭터가 일정한 거리만큼 왕복 이동하도록 Auto Move 기능을 추가했으며, 네트워크 지연을 의도적으로 증가시켜 일반적인 충돌 판정과 Rewind 판정의 차이를 확인할 수 있도록 구성했습니다.

// 05 — IMPROVEMENT

Further Improvements

현재 구현은 단순한 액터 Transform을 기준으로 테스트한 프로토타입입니다. 실제 캐릭터와 애니메이션이 적용된 게임에서는 각 캐릭터의 본에 연결된 Collision Transform까지 기록하여 보다 정확한 Hitbox Rewind 시스템으로 확장할 수 있습니다.

다만 모든 본의 Transform을 매 Tick마다 기록할 경우 메모리 사용량과 서버 연산량이 증가하기 때문에 필요한 Collision 데이터만 저장하는 방식으로 최적화할 필요가 있습니다.

또한 클라이언트에서는 과거 데이터를 저장할 필요가 없기 때문에 Authority가 없는 경우 Component Tick을 비활성화하는 방식으로 추가적인 최적화가 가능합니다.
